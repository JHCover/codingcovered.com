Work

What I've built, and how it was proven

PRINTgenie · 2023 to now

Moving a live backend from PHP to Java

The problem
PRINTgenie, a direct-mail marketing platform for real-estate professionals, ran on a Laravel API that was getting harder to change. Paying customers used it every day.
What I did
Rebuilt 137 endpoints as Java plugins on AWS (S3, SQS, Terraform). Repointed the React frontend one endpoint at a time, then retired the Laravel routes left behind.
How it was proven
A parity harness compares each endpoint with the PHP original, including auth failures and validation errors. Audit tooling lists every endpoint the live system serves and flags drift from the plan. The QA team signs off each release.

PRINTgenie · mobile

Keeping a field app current

The problem
Real-estate professionals use the company's Expo app out in the field. It has to keep up with SDK releases and app store rules without breaking for them.
What I did
Lead developer, with about 75% of the app's commits. Releases through EAS, crash monitoring with Sentry, and SDK upgrades through Expo 57 and React Native 0.86.
How it was proven
QA tests real iOS and Android builds before each release, and Sentry shows what users actually hit.

Holodeck · 2026

An AI dev team with guardrails

The problem
I wanted AI coding agents that could work unattended for hours without drifting off task, overspending or breaking the build.
What I did
Built a system of specialist agents that take work by voice or Discord. Each one works in its own git worktree, passes review gates before its work merges, and runs under spend metering, a concurrency limit and a time limit.
How it was proven
About 7,000 commits, more than 1,300 merged pull requests and more than 600 test files in four months. Since September, every change has reached the main branch through a pull request and automated gates.
